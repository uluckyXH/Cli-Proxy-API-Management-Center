# 管理页面发布脚本说明

本文说明如何用 `shell/release-management-html.sh` 在本地构建前端管理页面，并上传到 GitHub Release。CPA 后端会从 Release 里下载 `management.html`。

## 适用场景

当前前端仓库构建出来的是单文件 HTML：

```text
dist/index.html
```

后端固定查找的 Release Asset 名称是：

```text
management.html
```

所以发布流程就是：

```text
npm ci
VERSION=<版本> npm run build
cp dist/index.html dist/management.html
gh release create <版本> dist/management.html
```

脚本把这些步骤封装成一个命令。

## 前置条件

需要安装这些命令：

```bash
node --version
npm --version
git --version
gh --version
```

需要登录 GitHub CLI：

```bash
gh auth status
```

如果未登录：

```bash
gh auth login
```

## 基本用法

在前端仓库根目录执行：

```bash
shell/release-management-html.sh v6.10.0-usage.2
```

脚本会：

1. 检查工作区是否干净。
2. 检查本地和远端是否已有同名 tag。
3. 检查 GitHub Release 是否已存在。
4. 执行 `npm ci`。
5. 执行 `VERSION=<版本> npm run build`。
6. 复制 `dist/index.html` 到 `dist/management.html`。
7. 计算 `management.html` 的 SHA256。
8. 用 `gh release create --target <当前提交>` 创建 GitHub Release。
9. 上传 `dist/management.html`。

脚本不会单独执行 `git push origin <tag>`。这样可以避免和仓库里基于 tag 的 GitHub Actions 同时抢着创建 Release。

## 常用命令

正常发布：

```bash
shell/release-management-html.sh v6.10.0-usage.2
```

跳过依赖安装，复用已有 `node_modules`：

```bash
shell/release-management-html.sh v6.10.0-usage.2 --skip-install
```

指定 GitHub 仓库：

```bash
shell/release-management-html.sh v6.10.0-usage.2 --repo uluckyXH/Cli-Proxy-API-Management-Center
```

指定远端：

```bash
shell/release-management-html.sh v6.10.0-usage.2 --remote origin
```

这里的 `--remote` 只用于检查远端 tag 是否已存在，不会单独向该 remote 推送 tag。

允许在工作区有未提交改动时发布：

```bash
shell/release-management-html.sh v6.10.0-usage.2 --allow-dirty
```

不建议常用 `--allow-dirty`。它适合你明确知道要发布当前本地未提交状态时使用。

查看帮助：

```bash
shell/release-management-html.sh --help
```

## 版本号规则

脚本要求版本号以 `v` 开头，例如：

```text
v6.10.0-usage.2
v6.10.0-usage.3
v6.11.0-usage.1
```

原因：

- 前端仓库的 GitHub Actions release workflow 也是监听 `v*` tag。
- 保持 Release 版本命名一致，后续查找更清楚。

如果版本号已经发布过，脚本会停止，不会覆盖已有 Release。

## 后端配置

CPA 后端要使用你的前端 Release，需要在 `config.yaml` 里配置：

```yaml
remote-management:
  panel-github-repository: "https://github.com/uluckyXH/Cli-Proxy-API-Management-Center"
```

后端会请求：

```text
https://api.github.com/repos/uluckyXH/Cli-Proxy-API-Management-Center/releases/latest
```

并下载 latest release 里的：

```text
management.html
```

## 重新拉取管理页面

如果后端本地已经缓存了旧页面，可以删除本地缓存后再访问 `/management.html`。

常见默认位置是后端配置文件同目录下的：

```text
static/management.html
```

删除示例：

```bash
rm static/management.html
```

如果你设置了 `MANAGEMENT_STATIC_PATH`，以该环境变量对应路径为准。

## 常见问题

### tag already exists

说明版本号已经用过。换一个新版本号：

```bash
shell/release-management-html.sh v6.10.0-usage.3
```

### GitHub Release already exists

说明 GitHub 上已有同名 Release。脚本不会自动覆盖，避免误删资产。建议使用新版本号。

### working tree is dirty

说明有未提交改动。推荐先提交：

```bash
git status --short
git add <files>
git commit -m "feat(usage): update management page"
```

如果你确认就是要发布当前本地状态：

```bash
shell/release-management-html.sh v6.10.0-usage.2 --allow-dirty
```

### gh auth status 失败

先登录 GitHub CLI：

```bash
gh auth login
```

确认当前账号有目标仓库的 Release 写权限。
